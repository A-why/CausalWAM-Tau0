# Experiment Runbook — CausalWAM-Tau0

Exact reproduction commands for the five formal experiments, plus the
environment check. Each entry records **config**, **checkpoint input**,
**output location**, and **expected GPU requirement**.

All commands run from the project root (`$CAUSALWAM_ROOT`). Every script
auto-detects the root, auto-sets `CUDA_VISIBLE_DEVICES`, and writes a
timestamped log + config snapshot under `logs/`.

Environments (see `ENVIRONMENT.md`):

| Env | Python | PyTorch | CUDA | Role |
|---|---|---|---|---|
| `tau0_wm` | 3.10 | 2.7.1+cu126 | 12.6 | τ0 SFT / RL |
| `robotwin` | 3.10 | 2.4.1+cu121 | 12.1 | RoboTwin closed-loop eval |

---

## 0. Environment check

```bash
bash scripts/00_env_check.sh
bash scripts/01_prepare_data.sh
```

- **Config**: (none — reads `outputs/multitask_init/final_ready_tasks.json` and
  the 49 data configs directly)
- **Checkpoint input**: 5 KEEP checkpoints (see `ENVIRONMENT.md`)
- **Output**: `logs/00_env_check_*.log`, `logs/01_prepare_data_*.log`
- **GPU**: none (validation only; prints visible GPUs)

Exit `0` on both = environment is ready.

## 1. Multi-task SFT initialization (τ0 init)

```bash
bash scripts/02_train_sft.sh
```

- **Config**: `configs/training/theta_init_multi_v0.yaml`
  (49-task balanced pass; `batch_size=1`, `lr=5e-5`, `bf16`, `train_steps=32340`,
  `seed=42`; fresh resume fields — no prior checkpoint)
- **Checkpoint input**: `checkpoints/tau0_wm/vam` (τ0 VAM pretrained)
  + `checkpoints/wan2.2-ti2v-5b/*` (VAE / T5 / backbone)
- **Dataset**: `datasets/tau0_robotwin_multitask_v0/` (49 tasks)
- **Output**: `outputs/theta_init_multi_v0/` (step checkpoints; the validated
  init already shipped is `checkpoints/theta_init_multi_v0/step_500`)
- **GPU**: 1× H100 80GB (`tau0_wm`; `batch_size=1`, `bf16`). Throughput variant:
  `configs/server_large/large_train.yaml` (`batch_size=4`, workers 8, grad-accum).

## 2. SFT / init evaluation (RoboTwin closed-loop)

Two processes — a long-running VAM server, then the eval orchestrator.

```bash
# terminal A — server (cuda:0, serves checkpoints/theta_init_multi_v0/step_500)
bash scripts/03_launch_vam_server.sh --background
tail -f logs/03_launch_vam_server_*.log   # wait for MULTITASK_TAU_SERVER_READY

# terminal B — 49-task eval (resumable)
bash scripts/06_eval_all.sh
```

- **Config**: suite manifest `outputs/multitask_init/final_ready_tasks.json`
  (49 READY tasks) + per-task `datasets/.../statistics_relative_v2.json`
- **Checkpoint input**: `checkpoints/theta_init_multi_v0/step_500`
- **Reward**: `ercag/official_reward.py` → `float(check_success())` (sparse {0,1})
- **Output**: `outputs/multitask_init/closed_loop_eval.json` (resumable;
  49 tasks × 3 episodes)
- **GPU**: 1× H100 80GB for the VAM server (`cuda:0`) + RoboTwin env in the
  `robotwin` env. The orchestrator is sequential (`parallel_workers=1`); see
  `configs/server_large/large_eval.yaml` for the large-server parallelism note.

## 3. Vanilla baseline (True Flow-GRPO, critic-free)

```bash
# optional: --snapshot S0  --k 4  --max-steps <budget>  --validate-only
bash scripts/04_train_vanilla.sh --max-steps <budget>
```

> ✅ **STATUS: PRODUCTION.** Config-driven via
> `configs/training/vanilla_production.yaml`. Reward is the official
> `ercag/official_reward.py` → `float(check_success())` (sparse {0,1}, read from
> the V3-B0 sign probe); checkpoint is `checkpoints/pbb2_turn_switch/step_802`;
> statistics is `datasets/tau0_robotwin_success_v3_lerobot/turn_switch/statistics_relative_v2.json`;
> observation is a real RoboTwin native snapshot (`native_snapshots/`). Advantage
> is group-relative (`TauTrajectoryGroup.compute_advantages()`), and the loop is
> multi-iteration PPO-clipped Flow-GRPO. **No ACVS, no dummy observation, no
> smoke data.** Set `--max-steps` to the production budget at run time
> (`training.max_steps` is an explicit placeholder).

- **Config**: `configs/training/vanilla_production.yaml`
- **Checkpoint input**: `checkpoints/pbb2_turn_switch/step_802` (policy)
- **Reward**: `ercag/official_reward.py` → `float(check_success())` ✅
- **Inputs (generated by `scripts/prepare_ercag_snapshots.sh`)**:
  - `outputs/v3b0_outcome_contract/native_snapshots/S0.pkl` (real observation)
  - `outputs/v3b0_outcome_contract/sign_probe_results.jsonl` (official reward)
  - `outputs/v3b1_acvs_positive_neutral/tau_candidates/candidates.jsonl` (candidates)
- **Output**: `outputs/vanilla_production_v0/`
- **GPU**: 1× H100 (`tau0_wm`; policy `cuda:0`)
- **Dry-run**: `bash scripts/04_train_vanilla.sh --validate-only` checks config
  parse, checkpoint/dataset existence, reward import, and rollout env init
  without running training.

## 4. ER-CAG training (native paired counterfactual + shared ValueHead)

```bash
# 1. capture inputs (5 sequential steps; see scripts/prepare_ercag_snapshots.sh)
bash scripts/prepare_ercag_snapshots.sh

# 2. train (optional: --snapshot S0  --k 4  --max-steps <budget>)
bash scripts/05_train_ercag.sh --max-steps <budget>
```

> ✅ **STATUS: PRODUCTION.** Config-driven via `configs/training/ercag_production.yaml`
> (multi-task compatible; `task`/`prompt`/statistics/snapshot paths are templated).
> `eval/r2c_joint_rl_smoke.py` implements the full ER-CAG method (`G_i = Q_i − Q_0`,
> shared `ValueHead`, native future hook, official reward, 4/4 gradient gates).
> No smoke defaults remain — `--max-steps` is supplied at run time
> (`training.max_steps` is an explicit placeholder, not a smoke cap).

- **Config**: `configs/training/ercag_production.yaml`
- **Checkpoint input**: `checkpoints/pbb2_turn_switch/step_802` (policy) +
  `checkpoints/tau0_wm/simulator/diffusion_pytorch_model.bin` (frozen world model)
- **Reward**: `r_t = float(check_success())` read from the outcome contract ✅ correct
- **Inputs (generated by `scripts/prepare_ercag_snapshots.sh`)**:
  - `outputs/v3b0_outcome_contract/native_snapshots/S0.pkl`
  - `outputs/v3b0_outcome_contract/hold_reference.json`
  - `outputs/v3b0_outcome_contract/sign_probe_results.jsonl`
  - `outputs/v3b0_acvs_positive_neutral/sde_candidates/candidates.jsonl`
  - `outputs/v3b1_acvs_positive_neutral/tau_candidates/candidates.jsonl` +
    `hold_actions.json` (hold reference + tau-relative action chunks)
- **Output**: `outputs/ercag_production_v0/`
- **GPU**: 2× H100 (policy `cuda:0`, simulator + ValueHead `cuda:1`)

## 5. Final / multi-seed evaluation

Same command as §2; the orchestrator is resumable and idempotent, so it can be
re-run per seed or across the full 49-task suite:

```bash
bash scripts/06_eval_all.sh                         # full 49-task suite
bash scripts/06_eval_all.sh --tasks turn_switch      # single task
bash scripts/06_eval_all.sh --launch-server          # auto-start server if down
```

- **Config / checkpoint / output / GPU**: as §2.
- **Seeds**: episode/seed convention frozen at 3 per task
  (`episodes_per_task: 3` in `configs/server_large/large_eval.yaml`).

## Dependency order

```
00 env check ──► 01 data check
                    │
        ┌───────────┴────────────┐
        ▼                        ▼
02 SFT init               (03 VAM server on step_500)
        │                        │
        └──► 03 VAM server ──────┴──► 06 eval (SFT / init / final)

prepare_ercag_snapshots.sh ──► 04 vanilla / 05 ER-CAG (step_802 policy)
```

RL experiments (04 vanilla, 05 ER-CAG) are **independent** of SFT and consume
`checkpoints/pbb2_turn_switch/step_802`. Both are production-ready but gated on
the runtime capture step `scripts/prepare_ercag_snapshots.sh`, which generates
the snapshot/candidate/reward inputs they share.
